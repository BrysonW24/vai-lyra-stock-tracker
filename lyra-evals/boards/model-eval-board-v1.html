How the number was earned

The first run printed lift 2.77×. Adversarial review dismantled it before it was reported — each fix removed a real leak. The surviving number is smaller and true; the holdout then confirmed it out-of-time on a favourable regime.

Standing rule adopted: any lift above ~2× from this feature set triggers a mandatory leakage decomposition before the number is reported anywhere.

The standing suite

One command family runs the whole loop, and every cycle appends to lyra-evals/model-metrics-history.jsonl with the corpus hash — the grade trajectory is auditable.

npm run worker:emerging-winner-backtest -- build · retrain · compare · eval · holdout (one-shot) · promote · record

Regression layer: 509 Python tests (40+ new pins this cycle: purge units, EDGAR as-of discipline, label honesty, corpus integrity, forced-promotion audit) + 1,174 vitest tests + the drift guard. Rules: random-sample slice is always the headline · >2× lift triggers leakage decomposition · the holdout is never iterated against · surfacing promotion is founder-gated on live calibration, never on backtest numbers.

Read the numbers with these caveats. The corpus is survivor-biased (delisted names absent — the ruin class is censored, precision is an optimistic bound). Curated names were quarantined from training and headline metrics. still_listed excluded 0 winners (inert here); liquidity_grew excluded 457. Holdout 1.72× was one favourable regime; the claim is the interval, not the point. Deployment restatement at a 3% base: ≈5.6% top-pick precision.
