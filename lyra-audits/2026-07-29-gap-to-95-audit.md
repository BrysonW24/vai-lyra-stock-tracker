# Lyra Gap-to-95 Audit - 2026-07-29

Follow-up to the 2026-07-27 user-readiness audit. That audit scored the estate 82.3/100 and a
remediation wave (v0.83.0 -> v0.89.0) took **all 16 verticals to >=90**. This audit asks the next
question: **what specifically closes the gap from where each vertical sits now to a 95/100 bar?**

- **Method:** one read-only auditor per vertical, at v0.89.0 (HEAD `f731153`). Each auditor re-read
  its 2026-07-27 section, verified on disk which of the old gaps are now CLOSED (crediting only fixes
  it could see), re-scored from current disk state, and enumerated the concrete remaining gaps to 95
  with file:line evidence, the specific fix, effort (S<2h / M<1d / L>1d) and rubric points recovered.
- **Rubric (sums to overall):** functionality/25 + correctness/25 + resilience/20 + coverage/15 + polish/15.
- **95 bar:** near-flawless functionality + correctness, strong resilience, coverage >=14/15 and
  polish >=14/15, no open correctness defect, no built-but-unwired path on the user's primary journey.
- **House rules the fixes must obey:** deterministic engine decides / AI only explains and never
  invents a number; tests must not depend on machine timezone; "built, tested, green, never wired" is
  a real defect; prefer pure-function extraction over heavy RTL.

> Note on scores: these are the fresh auditors' INDEPENDENT re-scores from current disk. They differ
> slightly from the wave-7 re-audit baseline (e.g. V1 90->92, V3 90->91, V6 90->91, V8 91->94) because

## Cross-cutting patterns (what actually holds the estate below 95)

The remediation wave closed the load-bearing correctness and reachability defects. What remains is a
tight, recurring set - almost every core vertical loses its last 3-5 points to the same handful of
causes:

1. **Server-side / orchestration branches ship untested while the pure/Solo paths are pinned.** The
   remediation extracted and tested the deterministic decision helpers (great), but the account-backed
   read mappers (V2 `mapPortfolio`/`mapWatchlist`/`deriveSignalChanges`), the PUT rollback + DELETE
   wiring (V4), the inbound-webhook parsers + token-bucket (V6), the `handleFinish` save-orchestration
   sequencing (V7), and the `onboarded` metadata writer (V8) are all uncovered. This is the single
   biggest lever - it is where nearly every vertical's +2 coverage points live, and it is closable by
   the repo's own proven pattern (pure-function extraction + thin integration test, not RTL).

2. **One genuine correctness defect, not just polish: the onboarding gate can release on a partial
   failure.** `onboarding/page.tsx:270-286` writes `onboarded=true` (which `middleware.ts:134-137`
   trusts to release the mandatory-onboarding gate) BEFORE the watchlist/portfolio saves and before
   the `shouldBlockCompletion` early-return. A save that 401s followed by an abandon leaves a user
   past the gate with an empty book. This is the **highest-value single fix in the estate** (surfaced
   independently by both V7 as correctness and V8 as coverage; effort S, scoreGain 3). Fix: move the
   `updateUser({onboarded:true})` call to run only AFTER the save-success check passes.

3. **Cross-instance (serverless) state still in-memory on secondary paths.** The AI hosted-budget got
   a Redis/Upstash-backed shared store (v0.53), but the same fix was never applied to the last
   hosted-key AI route (V5 community scout-brief still calls the in-memory `chargeHostedBudget`) or to
   the inbound-webhook token-bucket + telegram sender dedupe (V6, `new Map` in module memory). Same
   class, same fix, low effort.

4. **Built-but-never-wired residue on operator/secondary surfaces.** Not on any primary user journey,
   but each caps functionality below the top band: the `research_analyst` agent endpoint has no UI
   caller (V5); the AI Ops dashboard + `/api/ai/metrics` + `/api/ai/insights` read an in-memory audit
   store the Supabase-writer prod deploy never fills, so they render "0 runs" in production (V5).

5. **44px touch-floor stragglers.** The remediation bumped the primary controls; a few secondary ones
   were missed - the Explore-drawer close button is 32px (V3), the add-holding/add-watch-rule inputs
   are h-8/h-9 (V4). Pure polish, all effort S.

**Bottom line for the core:** the path to 95 is dominated by **test coverage of already-shipped
server/orchestration code** (patterns 1 + the coverage half of 2), plus **one real correctness fix**
(the onboarded-ordering hole), plus **two same-class serverless-state ports** (pattern 3) and a
handful of **S-effort polish nits** (pattern 5). No vertical needs a new feature to reach 95; the work
is hardening and pinning what already ships. Every projected-if-closed lands at 95-97.
